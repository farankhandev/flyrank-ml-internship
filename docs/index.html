Machine Learning for Prioritizing Declining Content

Can machine learning help identify which content items should receive human review first when their search performance shows signs of decline?

Author: Faran Khan Lane: Machine Learning Date: September 6, 2026
Abstract Problem Data Method Results Limitations Recommendations Reproducibility

Abstract

This study asks whether machine learning can help prioritize content items that show signs of declining search performance. I compare a Random Forest classifier with a Logistic Regression baseline using historical performance and query-level signals. On a client-level holdout test set, the Random Forest achieved a ROC-AUC of 0.604 compared with 0.504 for the baseline, and achieved Precision@50 of 0.880 compared with 0.460. These results suggest that the Random Forest can provide a useful ranking signal for directing limited human review capacity. The result is treated as a decision-support experiment rather than evidence that content changes will cause future search performance improvements.

1. Problem & Research Question

This project supports the decision of which content items should receive human review first when their search performance shows signs of decline.

  • Unit of analysis: Content item/page.
  • Output: A model score and ranking of content items by likelihood of belonging to the defined declining-performance group.
  • Human action: A reviewer investigates high-priority pages before deciding whether a content change is appropriate.
  • Cost of a wrong call: A page may receive unnecessary review, while a genuinely declining page may be missed or reviewed later.
Important framing: The model is a decision-support tool. It does not prove that changing a page will improve future search performance.

2. Data

The analysis uses the FlyRank internship warehouse full release hosted on Hugging Face.

Data used

  • dim_clients — client-level metadata and data-history information.
  • dim_content — content-level metadata.
  • fact_content_daily_performance — daily search performance data.
  • fact_content_query_90d — aggregated content/query-level signals.

Modeling window

The modeling dataset uses a 60-day performance window split into two 30-day periods. Content items were required to have at least 100 impressions in the previous 30-day period.

Data safety

Client names, domains, URLs, search queries, and other client-identifying information were excluded from the public-facing analysis. Pseudonymous client identifiers were used only to create the client-level train/test split and were not used as model features.

Leakage consideration

The query-level signals came from an available 90-day query table. Because this window can overlap with the outcome period, these features create a potential temporal leakage concern. The results are therefore presented cautiously.

3. Methodology

Prediction target

A content item was labeled as declining when its latest 30-day impressions were less than 80% of its previous 30-day impressions, representing an observed decline of more than 20%.

Features

  • imp_prev30 — previous 30-day impressions
  • visible_queries — visible query count
  • rare_share — rare-query impression share
  • anon_share — anonymized-query impression share
  • top_query_share — top-query impression share

Model

I trained a Random Forest Classifier with 200 trees and a fixed random seed of 42. The model was selected because it can capture nonlinear relationships and interactions between the available signals.

Baseline

Logistic Regression was used as the baseline. Both models received the same five features and were evaluated on the same client-level holdout test set.

Validation

I used GroupShuffleSplit to keep clients separated between training and testing. Approximately 75% of modeling rows were used for training and 25% for testing.

The final test set contained 51,702 rows from 13 clients.

Evaluation metrics

Because the practical goal is prioritization, the primary evaluation focuses on ROC-AUC and Precision@K rather than overall accuracy.

4. Results

The Random Forest achieved stronger ranking performance than the Logistic Regression baseline on the same client-level holdout test set.

Metric Logistic Regression Random Forest
ROC-AUC 0.504 0.604
Precision@50 0.460 0.880
Precision@100 0.550 0.870
Precision@500 0.546 0.840
Key result: At the top 50 ranked items, 88% were labeled as declining with the Random Forest, compared with 46% for the Logistic Regression baseline.

Model performance

The Random Forest achieved a ROC-AUC of 0.604, compared with 0.504 for Logistic Regression. It also produced substantially higher Precision@K values.

Accuracy is not the main objective

The Random Forest test accuracy was approximately 61.3%, while Logistic Regression achieved approximately 65.8%. The Random Forest was therefore not more accurate overall.

This is important because the intended use case is prioritization. The strongest practical result is the model's ability to concentrate declining items near the top of the ranking.

5. Limitations

  • The client-level holdout provides a stronger test of generalization, but also makes the prediction task more difficult.
  • The model predicts the defined declining-impressions label. It does not prove that refreshing content will improve future performance.
  • The dataset is an anonymized internship dataset and should not be interpreted as evidence about any specific company or website.
  • The available features do not capture every factor that can affect search performance, such as search-engine changes, changing search intent, or competitive shifts.
  • The available 90-day query signals may overlap with the outcome period, creating a potential temporal leakage concern.
  • The Random Forest performed better on ranking metrics in this experiment, but that does not establish that it will perform equally well on every future dataset or client.
Honest framing: This should be treated as a prioritization experiment and decision-support tool, not a production forecasting system.

6. Ranked Recommendations

The model should be used to prioritize human review rather than automatically change content.

  1. Review the highest-ranked pages first. Start with pages receiving the highest model scores.
  2. Investigate search and query signals. Review historical impressions and available query-level signals for high-priority pages.
  3. Review content before making changes. Consider search intent, content quality, freshness, competition, and whether the page still meets user needs.
  4. Prioritize limited resources. Use the ranking when a team cannot investigate every page.
  5. Monitor results after changes. Measure subsequent search performance rather than assuming that a model recommendation guarantees improvement.

Recommended workflow

Model ranking → Human review → Content decision → Refresh/test → Monitor performance
