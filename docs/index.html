Machine Learning for Prioritizing Declining Content

A practical machine learning study exploring whether content showing signs of declining search performance can be prioritized for human review.

Faran Khan · Machine Learning · FlyRank ML Internship · 2026

Abstract

This project examines a practical content-review problem: when a team is responsible for a large number of pages, how can it decide which pages should be looked at first when search performance begins to decline? Using the FlyRank internship dataset, I tested whether historical search-performance and query-level signals could be used to rank content showing signs of decline.

I trained a Random Forest classifier and compared its results with a Logistic Regression baseline using a client-level holdout split. The Random Forest achieved a ROC-AUC of 0.604, compared with 0.504 for the baseline, and reached 0.880 Precision@50.

The results indicate that machine learning may be useful for narrowing a large content-review workload to a smaller set of higher-priority items. At the same time, the experiment does not show that changing a page will improve its future search performance. I therefore treat the model as a decision-support tool for organizing human review, rather than as a system that should make content decisions automatically.

1. Problem

Case study framing: This paper uses the FlyRank content dataset to study a practical prioritization problem: when search performance changes across a large collection of pages, a team may need a way to determine where human review should start. The machine learning system tested here addresses that first step by ranking content items that show signs of decline.

Research Question

Can machine learning help prioritize content items that show signs of declining search performance?

The motivation for this question is fairly practical. A team may be responsible for a large number of pages but have limited time to investigate every change in search performance. In that setting, simply identifying declining content is not enough. The more useful question is which items should receive attention first.

I use the FlyRank internship dataset as a case study of this prioritization problem. The experiment tests whether the historical search-performance and query-level signals available in the dataset can produce a useful ranking of content items showing signs of decline.

The intended workflow is to use the model to narrow the initial review list, investigate the highest-ranked items, and then have a human reviewer decide whether a page actually needs to be changed.

The model is intended to support that review process. It is not intended to make automatic content decisions or to claim that a particular change will improve rankings or traffic.

2. Data

Data Source

The analysis uses the FlyRank internship warehouse full release hosted on Hugging Face. I use this dataset as a public-safe case study for the content-prioritization problem described above.

The main tables used were:

  • dim_clients : client-level metadata and available history dates.
  • dim_content : content-level metadata.
  • fact_content_daily_performance : daily Google Search Console performance data.
  • fact_content_query_90d : content and query-level signals aggregated over the available 90-day window.

Modeling Window

I used a 60-day performance window split into two 30-day periods. The previous 30 days provide the historical context, while the latest 30 days are used to define the observed decline.

A content item needed at least 100 impressions in the previous 30-day period to be included in the comparison.

This resulted in 111,247 content items with sufficient performance history. After removing rows with missing values in the selected features, 102,203 items remained for modeling.

No client names, domains, URLs, search queries, or other private identifying information are included in this public analysis.

3. Methodology

Defining Declining Content

A content item was labeled as declining when its impressions during the latest 30-day period were less than 80% of its impressions during the previous 30-day period. In other words, the label represents an observed decline of more than 20%.

Features

The model used five available signals:

  • Previous 30-day impressions (imp_prev30)
  • Visible query count (visible_queries)
  • Rare-query impression share (rare_share)
  • Anonymized-query impression share (anon_share)
  • Top-query impression share (top_query_share)

Models

The main model was a Random Forest Classifier with 200 trees and a fixed random seed of 42. I used it to test whether the available signals could support a useful ranking of content items, rather than evaluating the problem only as a simple binary classification task.

For comparison, I used Logistic Regression as the baseline. Both models were trained using the same features and evaluated on the same test split.

Validation

I used GroupShuffleSplit to create a client-level holdout. Approximately 75% of the modeling data was used for training and 25% for testing, with clients kept separate between the two sets.

The final test set contained 51,702 rows from 13 clients.

This setup makes the evaluation more representative of the situation where a model is applied to content from clients it has not seen during training.

Evaluation

The main purpose of the model is prioritization, so I looked at both its overall ability to distinguish declining items and how well its highest-ranked items performed. The second part is particularly relevant to a review workflow where a team may only have enough time to investigate a small number of pages.

  • ROC-AUC
  • Precision@50
  • Precision@100
  • Precision@500

Leakage Consideration

The decline label was calculated from the latest 30-day impressions compared with the previous 30-day impressions.

One limitation of the current experiment is that the query-level signals come from the available 90-day query table. Because that period can overlap with the outcome period, some of these features may contain information from the same period used to define the outcome.

I therefore treat these results as an experiment in content prioritization rather than as a production-ready forecasting system.

The Random Forest produced a ROC-AUC of 0.604, compared with 0.504 for Logistic Regression. The difference is meaningful for this experiment because the Random Forest produced a stronger ranking signal on the held-out clients, although the overall discrimination remains modest.

The difference was more noticeable among the highest-ranked predictions. At the top 50 items, the Random Forest reached 0.880 Precision@50, meaning that 88% of those items were labeled as declining in the test set.

Overall classification accuracy tells a different story. The Random Forest achieved 61.3% accuracy compared with 65.8% for the Logistic Regression baseline. This is important because the purpose of this experiment is ranking, not simply maximizing classification accuracy.

The feature importance values give a directional view of which signals contributed most to the Random Forest's decisions. They should not be interpreted as causal effects.

Limitations

  • The client-level holdout provides a stronger test of generalization but also makes the prediction problem more difficult.
  • The model predicts the defined declining-impressions label. It does not show that a content refresh will cause performance to improve.
  • The dataset is anonymized, so the results should not be interpreted as evidence about a particular company or website.
  • The available features do not capture every factor that can affect search performance, including changes in search intent, competition, and search-engine behavior.
  • The 90-day query data may overlap with the outcome period, creating a potential temporal leakage concern.
  • Results from this experiment may not generalize equally to future datasets or clients.

Overall, the model should be treated as a decision-support and prioritization tool. A human reviewer should make the final decision about whether a page actually needs to be changed.

6. Ranked Recommendations

1. Start with the highest-ranked pages

When review capacity is limited, begin with the pages at the top of the model's ranking. The Precision@50 result suggests that this smaller group contains a high concentration of content labeled as declining.

2. Look at the underlying search signals

A model score should be a starting point for investigation. Review historical impressions and available query-level signals before deciding whether a page needs attention.

3. Review the content itself

Before making a change, a human reviewer should consider search intent, content quality, freshness, competition, and whether the page still answers the user's needs.

4. Use the ranking when resources are limited

Teams do not always have enough time to review every page. A ranked list can help direct limited review capacity toward a smaller set of higher-priority items.

5. Measure what happens after changes

If a page is refreshed, its search performance should be monitored afterward. The model should not be treated as evidence that a particular refresh will succeed.

Model ranking → Human review → Content decision → Refresh/test → Monitor
